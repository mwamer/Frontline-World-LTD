{{- /* Whether one person may be published, as a single boolean. This is the only place the rule lives. A person appears in the Expertise On Demand directory, in a course trainer grid and on a profile page only when all three conditions hold: publication_permitted the applicant said yes to a public profile visibility public, not private profile_status active, not inactive or archived The first condition is the applicant's own answer, carried across when the review approved them. It is stored in the record as publication_permitted and is copied from the application, never typed in by a reviewer, so "approved" can never quietly become "published": a record with visibility: public and publication_permitted: false stays off the site. A record with no publication_permitted field is one that was not created from an application — somebody already on the site, or one added by hand. Those records have no consent decision to check and keep publishing as they did, so the field defaults to true. That is a deliberate exception for existing people, and it stops applying as soon as a record carries the field. Everything else about a person — contact details, availability, files, the review history — lives in the private bucket under review/, which no template reads, so the gate is the only thing standing between a record and the published page. Call with a person: {{ partial "associate-is-public.html" $person }} */ -}} {{- $visibility := .visibility | default .status | default "public" -}} {{- $profile := .profile_status | default "active" -}} {{- /* Absent means the record predates the application pipeline, not that consent was refused. */ -}} {{- $permitted := true -}} {{- if isset . "publication_permitted" -}} {{- $permitted = eq .publication_permitted true -}} {{- end -}} {{- return (and $permitted (eq $visibility "public") (eq $profile "active")) -}}
